## 1. Shared mechanics

### 1.1 Body frame and where the line pulls

- Body frame `q` comes from the attitude component: Up, Front, Side (Side points towards the nose, as in tricks.md §2).
- Centre of mass: `CoMBody = (0,0,97)` cm above the deck. That is pelvis 80 + ankle 7 + 10.
- Shoulders, relative to the CoM: `S = (4, ±23, 42)` cm, from `RiderRig::ShoulderOffsetCm` (RiderRig.h:50) and the pelvis.
- Arm reach: `ArmReachCm = 0.97·(26.5+27) = 52`.

The attach point `A` (body frame, relative to the CoM) is a pure function, also used by the rig so the picture matches the physics:

```cpp
// RiderAttitudeComponent.h (new free functions in namespace LineAttach)
FVector LineAttach::AttachPointBody(const FBarState& Bar, const FVector& LineDirBody, float ArmExtension, const FLineAttachTunables& T);
FVector LineAttach::ClampToArmCone(const FVector& DirBody, const FVector& ConeAxisBody, float HalfAngleDeg);
```

| Bar state | A |
| --- | --- |
| Hooked | `HookBodyCm` (12,0,3). The research gives 0.10 to 0.15 m in front of the CoM. |
| Unhooked, both hands, bar in front | `lerp(HipHands(25,0,-5), S_mid + ClampToArmCone(d, ConeAxis, UnhookedArmConeDeg)·ArmReach, ArmExtension)` |
| FrontOnly / BackOnly | Same, but from that hand's shoulder `(4, ±23, 42)`. Front hand = +Side (the nose side). |
| BehindBack (blind) | `(-18, 0, -2)` cm, the lower back |
| Passing | Bar on the pass arc (§1.4) |
| Lost | No attach point. The force becomes the leash force, applied at the harness. |

The arm cone axis is `normalize(Front + 0.36·Up)`, 20° up from Front. `UnhookedArmConeDeg` is 100.

**Torque:** `τ = q·A × F_line` about the CoM. The translational force stays on the root's point mass, as today.

- With the arms extended and the line inside the cone, the arm vector is parallel to F. The torque is then `S_mid × F`, which is an effective lever of 0.42 m (the shoulders above the CoM). If the line leaves the cone, the lever grows to 0.6 to 0.9 m. tricks.md's 0.6 m sits at the top of that range.
- Hooked, the lever is the hook (0.12 m, along Front). With the kite in front, Front×d is about 0, so a hooked pop produces no raley. That falls out of the model.

**Why a raley emerges (pendulum check).** With the kite at 45°, tension 750 N, lever 0.42 m and I_side 12 kg·m²:
- ω₀ = √(750·0.42/12) = 5.1 rad/s.
- The torque pulls Up towards d, so the equilibrium is the body pointing at the kite, 45° from vertical.
- Starting upright, an undamped swing reaches 90° from upright, passes 60° at about 0.37 s, and comes back under in about 1.2 s. That matches a 1.3 s airtime.
- So a raley (more than 60°, no inversion) comes out with `HandsLineTorqueScale = 1`.

New in `FAttitudeInputs`: `FVector LineAttachBodyCm; FVector LineForceN; float HandsLineTorqueScale;` (1.0). The hooked scale is the existing T1.2 one.

### 1.2 Arm extension instead of sheet while unhooked

- **Real gear:** unhooked, the chicken loop is free, so the front lines pull it up to the stopper and the trim is fixed.
- **In the game:** `Kite->Sheet` is locked to `UnhookedStopperSheet` (0.6). The sheet input (right stick Y, triggers, Up/Down, mouse Y, motion-bar pitch) now drives `ArmExtension` (0 = bar at the hip, 1 = arms out).
  - Default `UnhookedArmExtensionDefault` is 0.7. It moves at `ArmExtensionRatePerSec` 3.0, the same persistent-bar semantics as `SheetRatePerSec`.
  - Effect: extended arms make a raley (long lever); bar to the hip makes inverts (short lever, about 0.15 m). Flip pre-wind auto-sets the target to 0.15 unless the player overrides it.
- **Hook point:** `AKiteRiderPawn::Tick` at KiteRiderPawn.cpp:888-891 (the sheet-rate integration) and `UpdateMotionBar` :565 (`SheetKite(MotionBarMapping.GetSheet(...))`). Both branch on `Bar.bHooked`.

## 2. Bar and pass state machine

New `Source/KiteSurf/Public/Tricks/BarState.h` and `Private/Tricks/BarState.cpp`. It is pure and has no UObject.

```cpp
enum class EBarHands : uint8 { Both, FrontOnly, BackOnly, None };
enum class EBarPlace : uint8 { Front, BehindBack, Passing, Lost };
enum class EBarLossCause : uint8 { None, OverGrip, PassUnderLoad, PassUnfinished, LinesWrapped };
enum class EPassKind : uint8 { Air, Surface };

struct FBarTunables {
  float GripLimitBW = 1.3f, GripLimitSeconds = 0.15f;
  float PassSlackTensionBW = 0.3f, PassSlackSeconds = 0.25f, PassLoseTensionBW = 0.6f;
  float PassDurationSeconds = 0.25f, PassBackToKiteDeg = 60.f, SurfacePassGraceSeconds = 0.3f;
  float PassRequestBufferSeconds = 0.2f, WrapHoldUpDot = 0.9f;
};
struct FBarInputs {
  float TensionN, BodyWeightN; FVector LineDirWorld; FQuat Body;
  bool bAirborne, bOnWaterRideable; float SecondsSinceTouchdown;
  bool bHookPressed, bPassPressed, bReleaseFront, bReleaseBack;
};
struct FBarEvents { bool bUnhooked=false, bHooked=false, bPassStarted=false, bPassDone=false; EPassKind PassKind=EPassKind::Air; EBarLossCause Lost=EBarLossCause::None; };

struct FBarState {
  bool bHooked = true; EBarHands Hands = EBarHands::Both; EBarPlace Place = EBarPlace::Front;
  float WrapDeg = 0;          // + = backside; lines round the body relative to the hips
  bool  bRouteBehind = false; // bar reached |W|>=90 behind the back (BS route, or a pass)
  float PassT = 0, PassSense = 0, SlackSeconds = 0, OverGripSeconds = 0, PassBufferLeft = 0;
  float LastLineAngleDeg = 0; bool bHasLineAngle = false;
  int32 PassesThisJump = 0; float WrapAtTakeoffDeg = 0;
};

namespace BarStateMachine {
  // Wrap is geometric: the line's azimuth in the body's Front/Side plane, unwrapped; held while the
  // line runs along the body (|d·Up| > WrapHoldUpDot), so rolls "round the lines" and S-bends do not wrap.
  float LineAzimuthDeg(const FQuat& Body, const FVector& LineDir);
  float BackToKiteDeg(const FQuat& Body, const FVector& LineDir);   // 0 = back square to the kite
  FBarEvents Step(FBarState& S, const FBarInputs& In, const FBarTunables& T, float Dt);
  bool CanLandRideable(const FBarState& S);                           // |W| ≤ 240 and not Lost
}

FBarEvents BarStateMachine::Step(FBarState& S, const FBarInputs& In, const FBarTunables& T, float Dt) {
  FBarEvents E; const float TBW = In.TensionN / FMath::Max(In.BodyWeightN, 1.f);
  if (S.Place == EBarPlace::Lost) return E;
  if (In.bHookPressed && In.bOnWaterRideable && S.Place == EBarPlace::Front && S.Hands == EBarHands::Both)
    { S.bHooked = !S.bHooked; (S.bHooked ? E.bHooked : E.bUnhooked) = true; }
  if (S.bHooked) { S.WrapDeg = 0; S.bRouteBehind = false; return E; }

  // grip
  S.OverGripSeconds = TBW > T.GripLimitBW ? S.OverGripSeconds + Dt : 0.f;
  if (S.OverGripSeconds > T.GripLimitSeconds) { S.Place = EBarPlace::Lost; E.Lost = EBarLossCause::OverGrip; return E; }

  // wrap
  const FVector UpW = In.Body.GetAxisZ();
  if (FMath::Abs(FVector::DotProduct(UpW, In.LineDirWorld)) < T.WrapHoldUpDot) {
    const float A = LineAzimuthDeg(In.Body, In.LineDirWorld);
    if (S.bHasLineAngle) {
      const float dW = -FMath::FindDeltaAngleDegrees(S.LastLineAngleDeg, A);   // body turning BS = line moving the other way
      if (S.WrapDeg < 90 && S.WrapDeg + dW >= 90) S.bRouteBehind = true;        // BS route: bar behind the back
      S.WrapDeg += dW;
      if (FMath::Abs(S.WrapDeg) < 90) S.bRouteBehind = false;
    }
    S.LastLineAngleDeg = A; S.bHasLineAngle = true;
  }
  if (S.Place != EBarPlace::Passing)
    S.Place = (FMath::Abs(S.WrapDeg) >= 90 && S.bRouteBehind) ? EBarPlace::BehindBack : EBarPlace::Front;

  // pass
  S.SlackSeconds = TBW < T.PassSlackTensionBW ? S.SlackSeconds + Dt : 0.f;
  S.PassBufferLeft = In.bPassPressed ? T.PassRequestBufferSeconds : FMath::Max(S.PassBufferLeft - Dt, 0.f);
  if (S.Place != EBarPlace::Passing && S.PassBufferLeft > 0 && TBW < T.PassSlackTensionBW
      && FMath::Abs(BackToKiteDeg(In.Body, In.LineDirWorld)) <= T.PassBackToKiteDeg) {
    S.Place = EBarPlace::Passing; S.PassT = 0; S.PassSense = S.WrapDeg >= 0 ? 1.f : -1.f;
    S.Hands = EBarHands::None; S.PassBufferLeft = 0; E.bPassStarted = true;
  }
  if (S.Place == EBarPlace::Passing) {
    if (TBW > T.PassLoseTensionBW) { S.Place = EBarPlace::Lost; E.Lost = EBarLossCause::PassUnderLoad; return E; }
    S.PassT += Dt / T.PassDurationSeconds;
    if (S.PassT >= 1.f) {
      S.WrapDeg -= 360.f * S.PassSense; S.bRouteBehind = true;   // same geometric spot, route switched sides
      S.Place = EBarPlace::BehindBack; S.Hands = EBarHands::Both; ++S.PassesThisJump;
      E.bPassDone = true; E.PassKind = In.bAirborne ? EPassKind::Air : EPassKind::Surface;
    } else if (!In.bAirborne && In.SecondsSinceTouchdown > T.SurfacePassGraceSeconds) {
      S.Place = EBarPlace::Lost; E.Lost = EBarLossCause::PassUnfinished; return E;
    }
  }
  if (FMath::Abs(S.WrapDeg) >= 270.f && !In.bAirborne) { S.Place = EBarPlace::Lost; E.Lost = EBarLossCause::LinesWrapped; }
  // single-hand releases (grab buttons unhooked, tantrum auto back-hand-off)
  if (S.Place == EBarPlace::Front && S.Hands == EBarHands::Both) {
    if (In.bReleaseBack) S.Hands = EBarHands::FrontOnly; else if (In.bReleaseFront) S.Hands = EBarHands::BackOnly;
  } else if (S.Place == EBarPlace::Front && !In.bReleaseBack && !In.bReleaseFront) S.Hands = EBarHands::Both;
  return E;
}
```

**How the model lands each case:**

| Trick | Wrap path | Landing |
| --- | --- | --- |
| BS 180, no pass | 0 → +180 | Blind (back to blind, raley to blind) |
| BS 180 + air pass | +180 → −180, route stays behind | Blind (blind judge) |
| FS 180, no pass | 0 → −180 round the front | Toeside (krypt) |
| BS 3 / KGB | 0 → +180, pass → −180, then 0 | Heelside |
| FS 3 / 313 / slim chance | mirrored | Heelside |
| 720 | needs 2 passes | Heelside |

**Pass degrees for naming:** `SpinDeg = 360·Passes·Sense + (W_land − W_takeoff)`, half turns = `round(|SpinDeg|/180)`. The code digit is {1→1, 2→3, 3→5, 4→7, 5→9, 6→10}.

**Pawn integration** (new members `FBarState Bar; FBarTunables BarTunables;`), inside `StepSimulation` KiteRiderPawn.cpp:745:
1. After `Kite->StepKite` (:758), call `StepBar(StepSeconds)`. It runs `BarStateMachine::Step` and handles the events:
   - unhook: `Kite->SetLowParkAssist(true, LowParkElevationDeg)`, sheet locked;
   - hook: low park off, sheet restored;
   - lost: `Kite->SetLeashed(true)`, and the record cause becomes `BarLost`. On the water, call `TriggerCrash()`. In the air, keep flying ballistically and crash on touchdown through the landing evaluator, because `TriggerCrash` zeroes Vz and freezes the rider mid-air (BoardMovementComponent.cpp:807).
   - pass started in the air: `Kite->RequestFlick(...)` if the flick assist is on.
2. The line force at :762 is unchanged except when Lost (leash cap).
3. The attitude step after `StepBoard` (:766) gets `LineAttachBodyCm = LineAttach::AttachPointBody(Bar, ...)`.

Pressing pass sets a flag consumed by the next step (Enhanced Input Started → `bPassPressedPending`). Hook presses work the same way.

### T3.6: Freestyle heat (size S, 1 PR)

**In `TrickScoring.h/.cpp`:**

```cpp
struct FFreestyleHeatRules { int32 Counting=4, MaxHeel=2, MaxVariety=3; float Bonus[5]={0,1,2,4,7}; int32 Attempts=7; };
struct FHeatResult { float Total; TArray<int32> CountingIdx; float VarietyBonus; };
FHeatResult ScoreFreestyleHeat(TConstArrayView<FScoredTrick> Tricks, const FFreestyleHeatRules&);
```

Algorithm:
1. Take the best score per family.
2. Sort within each group.
3. For h in 0..MaxHeel, set v = min(Counting−h, MaxVariety), sum the top h and top v, and keep the best sum.
4. Bonus = `Bonus[number of families counted]`.

**Heat flow:**
- `AKiteSurfGameMode::StartFreestyleHeat(int32 Attempts)` and console `kitesurf.Heat freestyle 7`.
- An attempt is an unhooked jump with more than 0.4 s airtime, or any bar-lost or crash.
- The HUD shows "Trick 3/7" and the counting list.

{
  const uint8 Half = FMath::Min<uint8>(S.PassSpinHalfTurns, 6);

    if (E.Move == S.FreestyleMove && (E.Sense == 0 || E.Sense == S.PassSense)
        && Half >= E.MinHalf && Half <= E.MaxHalf && S.Passes >= E.MinPass && S.Passes <= E.MaxPass) {

      if (OutDiff) *OutDiff = E.Diff; return N;
    }
  return TrickNaming::DescribeFallback(S);   // "Back roll + backside 540 pass to blind", capped at 4 parts
}

## 5. T4 strapless (outline)

- **PR 1 (board held by the feet).** `EBoardHold { Strapped, Pressed, Free }` on the pawn; `bStrapless` is gear (`UKiteSurfGameInstance`, gear screen). In the air the board stays `Pressed` while:
  - the crouch/press target (auto, or the load button) is at least 0.3;
  - the body angular rate is at most `StraplessStickMaxRateDegS` (500);
  - the angle between the body's Up and the board normal is at most 50°;
  - the rider's own acceleration over the step, with the kite included, does not exceed g·`StraplessPressMarginG` (0.4). Otherwise the board goes `Free`, i.e. T2.3's detached-board projectile, and a re-catch needs a press within 0.3 s.
  - Directional board: `SwitchStanceSpeedCmS` disabled (BoardMovementComponent.cpp:602); nose-first landings only; jibe input.
  - Test: `KiteSurf.Trick.StraplessBoardStaysPressed` (a tuck pop keeps it; a 700°/s spin loses it).
- **PR 2 (shove-it).** Kick = R3 + left stick X. The board yaws about its own normal relative to the body at `ShoveItRateDegS` (540). Release stops the spin, and the landing evaluator checks the board yaw against the velocity, so the board spin has to be timed to the airtime. Tracker: board half-turns, giving "Shove-it 1/2/3", and "Big spin" when body and board spin together.
  - Tests: `KiteSurf.Trick.ShoveItMustMatchAirtime` (released at 180 ± 20 lands; at 270 it is a crash with cause BoardNotAligned); `KiteSurf.Trick.NamesShoveIt`.
- **PR 3 (strapless board-offs).** No strap release step, but hand plants etc. reuse T2.3 sockets: hand stand, Jesus walk, hand varial.
- **PR 4 (scoring).** `ScoreStraplessHeat`: one trick per category, and only the first trick per tack counts. A tack is the sign of `dot(Velocity2D, Crosswind)`, with 2 s hysteresis. Test `KiteSurf.Trick.StraplessFirstTrickPerTack`.

## 6. Problems in docs/tricks.md against the code

1. **§5 is stale.** The physics rework has merged (#45). Code is now stepped in `StepSimulation` (KiteRiderPawn.cpp:745), and the zenith drift is the default (`bParkHoldAssist=false`, KiteComponent.cpp:87). §7's "T1 waits for items 1 and 2" is satisfied.
2. **§6.4 "kite assist parks at 45° instead of drifting to 12"** has to override both the main zenith drift (KiteComponent.cpp:662-670) and phase-2 A2's airborne overhead hold. The doc mentions neither.
3. **The sheet is wrong while unhooked.** The doc keeps the sheet in use. With real gear the trim is fixed at the stopper and the bar input should become arm extension (§1.2). Without that change the motion-bar mapping and the raley/invert distinction have no input.
4. **The ballistic target vs the model.** §1 says freestyle is ballistic, "same pop as `LoadPopBonus`". The pop height is fine, but the in-air line force at a 45° kite is about 0.5 BW vertical, about 4 m/s² of lift, so it fails "within 30% of g" unless measured and tuned (T3.1 PR 3). Treat it as a calibration item, not a given.
5. **Grip limit "jump scores as a crash":** `TriggerCrash` in the air zeroes Vz and freezes the rider (BoardMovementComponent.cpp:807-818). Bar loss in the air has to defer the crash to touchdown.
6. **§6.3 bindings** (LeftShift for the pass, RB for the grab) are forbidden by the existing KiteSurfHUDTests.cpp:136.
7. **Hands lever "0.5 to 0.7 m":** with arms along the line, the effective lever is the shoulder height above the CoM, 0.42 m. It only reaches 0.6 m or more when the line is outside the arm cone. The torque is `S×F`, not `(S + reach·d)×F`.
8. **§3.4 landing column.** "Frontside or backside 3, 5, 7 lands heelside or switch" and "KGB (5, 7) lands heelside" contradict geometry: an odd number of half turns leaves the body 180° from the kite, so 5s land blind or toeside. Fix the table or confirm against a clip.
9. **The "two passes from 7 upwards" rule** is fine for 7 and 9, but a 1080 ("10") under any wrap-conserving model needs three passes or lands wrapped.
10. **Blind judge vs raley to blind** differ only by an air pass. This is consistent only if a pass switches the wrap route without unwinding at that moment (the §2 model). Add this to the §9 sign-convention question.
11. **§3.6 variety bonus "by number of families used":** since only the best per family counts, that number equals the number of counting tricks. Check whether the rulebook means variety-group families.
12. **§6.4 "Blind and toeside take-offs come last" / T3.7 L:** the hydrodynamics barely change (the auto-heel is facing-independent, BoardMovementComponent.cpp:598). The size is driven by phase-2 item 3 re-basing, not by T3.7 itself.
